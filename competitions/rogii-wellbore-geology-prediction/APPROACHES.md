## Research: studying current 6.40-scoring public notebooks (2026-07-24, both since submitted 2026-07-25)

Researched current public notebooks self-reporting **LB 6.40** (e.g. `fleongg/rogii-codex-public-6-40-guard`, `pi500phys/rogii-public-6-40-guard-repro`) to see if they represent a genuinely new technique or a tuning tweak. Answer: same base pipeline lineage we already understand (`SUBMISSION_PROFILE = 'vp_balanced_modelpkg_005'`, nearly our exact config), plus **two new, well-defined post-processing layers** added on top. Pulled the full code (not just markdown) for both and ported each in isolation onto our own confirmed `working-note-no-override-ablation.ipynb` baseline — same one-change-at-a-time methodology that found the override problem in the first place, rather than adopting the bundled notebook wholesale.

| Layer | What it does | Leak-related? | Fork | Status |
| --- | --- | --- | --- | --- |
| **U-continuity fade** | Smooths the discontinuity between the last known prefix value and the first predicted hidden-tail value: `move = -clip(gap_u, -8ft, 8ft) * exp(-md_since / 240)`. Only reads `submission.csv` + the well's own `MD`/`Z`/`TVT_input` | **No** — legitimate physical/geometric continuity fix, nothing to do with train/test overlap | `notebooks/working-note-continuity-fade-ablation.ipynb`, pushed as `dalloliogm/rogii-continuity-fade-ablation` v1 | **Scored 7.111** (`54968618`) — statistically indistinguishable from the 7.102 no-override baseline given the noise band. Not clearly a win, but ran cleanly |
| **Capped overlap calibration** | Blends in a small, fixed **5.5%** of train's `TVT` at the exact matching row: `tvt = 0.945 * base_prediction + 0.055 * train_TVT_at_same_row`. Only activates when a test well's trajectory exactly matches a train well's (all 3 of ours do) | **Yes, explicitly.** Same signal as our full contact-override (scored 9.565, worse than baseline) at 5.5% weight instead of 100% | `notebooks/working-note-capped-overlap-ablation.ipynb`, pushed as `dalloliogm/rogii-capped-overlap-ablation` v1 | **Threw an exception** (`54968623`) — confirmed dead end per the forum finding that the visible-data overlap doesn't exist in the real hidden test set anyway |

Also confirmed independently (from this same notebook's own code, cell 59, "hidden-rerun submission contract"): other serious competitors explicitly build defensive contract-guards against Kaggle's grading re-execution — cross-validates our own hard-won discovery that "my kernel ran fine" doesn't guarantee grading survives it.

**Conclusion**: neither of these two ablations moved the needle. Combined with the model-package-only reliability collapse (3 attempts, 3 different outcomes), the current "target-free geosteering" pipeline family appears to have plateaued around ~7.1 with real execution instability. The path to meaningfully better and silver/gold-territory scores (5.7-6.0 per forum reports) almost certainly requires the genuinely different techniques found in forum research — neighbor-well curve transfer, azimuth-based splitting, and bimodal datum hedging — not further tweaks to this pipeline family. See Backlog.
