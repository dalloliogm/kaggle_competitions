## Research: studying current 6.40-scoring public notebooks (2026-07-24, both since submitted 2026-07-25)

Researched current public notebooks self-reporting **LB 6.40** (e.g. `fleongg/rogii-codex-public-6-40-guard`, `pi500phys/rogii-public-6-40-guard-repro`) to see if they represent a genuinely new technique or a tuning tweak. Answer: same base pipeline lineage we already understand (`SUBMISSION_PROFILE = 'vp_balanced_modelpkg_005'`, nearly our exact config), plus **two new, well-defined post-processing layers** added on top. Pulled the full code (not just markdown) for both and ported each in isolation onto our own confirmed `working-note-no-override-ablation.ipynb` baseline — same one-change-at-a-time methodology that found the override problem in the first place, rather than adopting the bundled notebook wholesale.

| Layer | What it does | Leak-related? | Fork | Status |
| --- | --- | --- | --- | --- |
| **U-continuity fade** | Smooths the discontinuity between the last known prefix value and the first predicted hidden-tail value: `move = -clip(gap_u, -8ft, 8ft) * exp(-md_since / 240)`. Only reads `submission.csv` + the well's own `MD`/`Z`/`TVT_input` | **No** — legitimate physical/geometric continuity fix, nothing to do with train/test overlap | `notebooks/working-note-continuity-fade-ablation.ipynb`, pushed as `dalloliogm/rogii-continuity-fade-ablation` v1 | Ran clean. Found and corrected a real boundary discontinuity across all 3 wells (mean move 0.13 ft, max 3.83 ft). **Submitted `54968618`, 2026-07-25, pending** |
| **Capped overlap calibration** | Blends in a small, fixed **5.5%** of train's `TVT` at the exact matching row: `tvt = 0.945 * base_prediction + 0.055 * train_TVT_at_same_row`. Only activates when a test well's trajectory exactly matches a train well's (all 3 of ours do) | **Yes, explicitly.** Same signal as our full contact-override (scored 9.565, worse than baseline) at 5.5% weight instead of 100% | `notebooks/working-note-capped-overlap-ablation.ipynb`, pushed as `dalloliogm/rogii-capped-overlap-ablation` v1 | Ran clean, all 3 wells activated the blend. **Submitted `54968623`, 2026-07-25, pending** |

Also confirmed independently (from this same notebook's own code, cell 59, "hidden-rerun submission contract"): other serious competitors explicitly build defensive contract-guards against Kaggle's grading re-execution — cross-validates our own hard-won discovery that "my kernel ran fine" doesn't guarantee grading survives it.

**Given the newly-discovered grading-time instability (see Tried table above), treat any single result from these two — good or bad — with real skepticism until corroborated by a repeat submission, same as the reproducibility tie-breaker in progress for model-package-only.**
